# 개발 노트 (작업 중 판단·막힌 점 기록)

작업 일시: 2026-11-22 (사용자 취침 중 자율 진행)

## 요청 사항
- 에픽세븐 방식(속도 기반 턴제, 3:3~3:5, 자동 전투, 무리를 깨면 오른쪽으로 달려가 다음 무리)
- 1장: 황건적 졸병 → … → 장각까지 여러 전투, 장각 도달 시 레벨이 많이 오른 상태
- 출진 전 위치 선정: 맨 앞(선봉)이 많이 때리고 많이 맞고 경험치를 가장 많이 받음
- 능력치: 유비(공 최저, 방 높음) / 관우(공·방 모두 높음) / 장비(공 최고, 방 최저)
- 자동 전투로 지면 안 됨. 단, 배치를 이상하게 하면 질 수 있는 난이도

## 판단·결정 기록
1. **격자 전술 → 에픽세븐식 전투로 교체**: 이전 격자 전투 코드(`grid.ts`, `battle.ts`)는 삭제했다(git 기록에는 남아 있음). 이야기 화면, 저장, 배포는 그대로 재사용했다.
2. **화면 방향은 세로 유지**: 에픽세븐은 가로 화면이지만, 지금까지 세로로 만들어 왔고 한 손 조작에 유리해서 세로(360×640)로 했다. 위쪽은 전장, 아래쪽은 스킬 패널이다.
3. **진형 규칙** (`src/core/combat.ts` 상단 상수):
   - 선봉: 공격력 ×1.15, 적의 단일 공격 대상이 될 확률 가중치 50%, 경험치 ×1.5
   - 중군: 공격력 ×1.0, 30%, 경험치 ×1.15
   - 후군: 공격력 ×0.9, 20%, 경험치 ×0.95
   - 적의 전체 공격은 진형과 관계없이 모두에게 맞는다.
4. **경험치 방식 변경**: "처치한 장수만 경험치"에서 **"때린 횟수 + 맞은 횟수(×진형 배율) + 처치 보너스"를 전투가 끝날 때 지급**하는 방식으로 바꿨다. 요청한 "선봉이 많이 때리고 많이 맞으며 경험치를 가장 많이 받는다"를 그대로 구현한 것이다. 유비의 회복·버프 행동도 1회 행동으로 친다. 그러지 않으면 유비만 레벨이 크게 뒤처졌다.
5. **1장 구성 (6개 전투)**: 탁현 출정(등무, 정원지) → 청주 구원(황건두령) → 광종 원군 → 영천의 불길(장량) → 곡양의 요술(고승, 장보) → 천공장군 장각.
   - **역사와 다른 점**: 연의에서는 동탁 구원(장각과 교전)이 장보와의 곡양 전투보다 먼저 나온다. 또 장각은 병사했다. "장각과의 만남을 마지막에" 두라는 요청에 맞춰 순서를 바꾸고, 장각과의 결전을 게임적 각색으로 넣었다.
   - "청주를 포위한 두령"은 연의에 이름이 없어서 가상의 적장(황건두령)으로 만들었다.
6. **숨 고르기 추가**: 무리 사이를 달려갈 때 체력 20%를 회복한다. 4~5개 무리를 체력 회복 없이 연달아 싸우면 소모전이 너무 심해서 후반 전투를 진형과 상관없이 졌다.
7. **난이도 조정 방법**: 자동 전투 시뮬레이터(`src/core/simulate.ts`)로 6가지 진형 × 수십 번씩 1장 전체를 돌려 가며 수치를 맞췄다.
   - 최종 결과 (40회): 관우 선봉 → 40/40 완주, 패배 0, 전사 0 / 장비 선봉 → 패배 후 재도전 29~45회, 장비 전사 13~16회
   - 이 기준은 `tests/balance.test.ts`가 회귀 테스트로 지킨다. 수치를 바꾸면 이 테스트로 확인할 것.
   - 주요 조정 수치: 방어력의 피해 감소 효과 강화(`DEF_WEIGHT` 1.5), 적 공격력 배율(`ENEMY_POWER` 1.2), 적 전체 공격 위력 하향, 장각 약화
8. **"자동으로 지면 안 된다"의 해석**: 관우 선봉(가장 상식적인 배치)이면 자동 전투로 절대 지지 않게 맞췄다. 유비 선봉은 가끔 지고(군주를 앞에 세우는 위험), 장비 선봉은 자주 진다. 관우 선봉에 장비 중군(유비 후군) 배치는 장각전에서 장비가 드물게(약 5%) 전사한다.
9. **진형 화면 조작 수정**: 처음에는 한 칸이 항상 선택된 상태여서, 첫 탭에 바로 자리가 바뀌는 혼란이 있었다(테스트 스크립트도 이것 때문에 의도와 다르게 배치됐다). "탭해서 고르기 → 다른 자리 탭으로 교체 → 선택 해제" 방식으로 바꿨다.
10. **자동 전투 기본값 ON**: "자동으로 플레이돼야 한다"는 요청에 따라 기본값을 켜 두었다. 설정은 브라우저에 저장된다. 자동을 끄면 스킬을 직접 고를 수 있다.
11. **패배 시 기록 없음**: 진 전투에서 얻은 경험치와 전사는 저장하지 않는다. 진형 화면으로 돌아가 다시 도전한다. 이긴 전투의 전사만 영구 기록된다.
12. **이야기 화면의 적 화자**: 장각이 말할 때 '장'(장비와 같은 글자)으로 표시되는 문제를 고쳤다. 이제 적은 빨간 원에 고유 글자('각')로 나온다.
13. **2D 드래그 진형 (v0.3)**: "전투 화면과 같은 화면에서 3명을 2차원 칸에 드래그로 배치"하라는 요청에 따라 3×3 칸으로 바꿨다. 결정한 규칙은 다음과 같다.
   - **열이 역할을 정한다**(선봉, 중군, 후군). 행은 서 있는 위치만 바꾼다. 행에 효과를 주는 방식(같은 행의 앞 장수가 뒤를 막아 주기 등)도 생각했지만, 규칙이 복잡해져서 일단 넣지 않았다.
   - 같은 열에 여러 명을 세울 수 있게 했다. 이것만으로는 "전원 선봉"(셋 다 공격력 +15%, 경험치 ×1.5)이 항상 이득이라서 **받는 피해 배율**(선봉 100%, 중군 90%, 후군 80%)을 추가했다.
   - 시뮬레이션 결과 (40회):

     | 배치 | 완주 | 재도전 | 전사 |
     |---|---|---|---|
     | 관우 선봉, 유비 중군, 장비 후군 | 40/40 | 0 | 0 |
     | 관우 선봉, 유비·장비 후군 | 40/40 | 0 | 0 |
     | 전원 후군 | 40/40 | 0 | 1 |
     | 관우·장비 선봉, 유비 후군 | 39/40 | 4 | 4 |
     | 전원 선봉 | 39/40 | 9 | 3 |
     | 장비 선봉, 유비 중군, 관우 후군 | 32/40 | 43 | 16 |

     전원 선봉은 빨리 크지만 위험하고, 전원 후군은 안전하지만 경험치가 적다.
   - 3×3이 되면서 위아래 칸이 가까워져, 전투 화면에서 장수 밑에 붙던 "선봉/중군/후군" 글자를 없앴다. 차례가 온 장수의 자리는 아래 패널에 표시된다.
   - 예전 저장 데이터(순서 목록)는 자동으로 칸 배치로 바뀐다.
14. **장수 일러스트 (v0.4)**: 유비 그림을 넣었다. 그림은 사용자가 Gemini로 만들었다.
    - 첫 결과는 "너무 AI 같다"는 평이었다. 세밀함 줄이기, 2단계 셀 채색, 선 굵기 변화, 색 수 제한, 비대칭 포즈를 요청하는 프롬프트로 다시 만들었다.
    - 2×2 시트를 `tools/cut-sheet.mjs`로 잘라 흰 배경을 투명하게 만든다. 테두리에 남는 흰 띠도 지우고, 네 포즈를 같은 비율로 줄인다. 이미지 라이브러리를 설치하지 않으려고 pngjs와 macOS `sips`만 썼다.
    - 전투: 기본 포즈로 서 있다가 공격할 때는 공격 포즈, 필살기와 회복을 쓸 때는 필살기 포즈로 바뀐다. 차례 표시는 발밑의 금색 타원이다.
    - 이야기 화면에는 초상화가 나오고, 진형 화면에서도 그림을 끌어 배치한다.
    - 관우와 장비는 아직 원형 말이다.
15. **달리기와 공격 동작 (v0.5)**: 이미지 AI에 "조금씩 다른 4프레임 달리기"를 요청하면 거의 같은 그림 4장이 나왔다. 그래서 확실히 다른 2프레임만 받고, 튕김, 기울기, 먼지는 코드로 만들었다. 받은 달리기 시트의 두 번째 프레임이 왼쪽을 보고 있어서 도구에 좌우 뒤집기(`:flip`)를 넣었다. 공격 시트는 동작 4종이 잘 나와서 그대로 썼다.

## 막혔던 점과 해결
- **이 맥의 `/etc/hosts`에 localhost가 없음**: 개발 서버와 Vitest가 `ENOTFOUND localhost`로 실패했다. 개발 서버를 `0.0.0.0`에 띄우도록 설정해서 피했다. 이후 사용자가 hosts 파일을 직접 고쳤다.
- **회사 npm 레지스트리**: 전역 npm 설정이 사내 레지스트리를 가리켜 집에서 설치가 실패했다. 프로젝트 `.npmrc`로 공개 레지스트리를 지정했다.
- **첫 난이도 조정 실패**: 처음 수치로 돌려 보니 진형과 상관없이 장보, 장각 전투에서 전멸했다. 원인은 (1) 적이 레벨당 강해지는 폭이 아군보다 크고, (2) 4~5개 무리를 회복 없이 연달아 싸우는 소모전, (3) 진형으로 피할 수 없는 적 전체 공격이 너무 강한 것이었다. 적 성장률 하향, 숨 고르기 추가, 적 전체 공격 하향, 방어력 효과 강화, 장각 약화로 해결했다.

## 확인한 것
- 단위 테스트 23개 + 난이도 회귀 테스트 2개 통과
- 헤드리스 크롬 자동 조작으로 확인한 흐름:
  - 새로 시작 → 이야기 → 진형 바꾸기 → 출진 → 자동 전투로 1화 4개 무리 클리어 → 마무리 대사 → 결과(경험치, 레벨업) → 저장 확인
  - 2화 진형 화면 → 자동 끄기 → 직접 스킬 선택 → 적 탭으로 공격
- 콘솔 에러 없음
- (v0.3) 진형 드래그를 마우스와 터치 이벤트로 모두 확인했다. 빈칸으로 이동, 맞바꾸기, 칸 밖에 놓으면 제자리 복귀가 동작하고, 저장된 칸대로 전투 화면에 선다.

## 확인하지 못한 것 / 남은 일
- 2~6화를 실제 화면에서 끝까지 플레이해 보지 않았다. 전투 로직은 시뮬레이터로 수천 번 검증했지만, 화면은 1~2화만 확인했다.
- 실제 폰에서의 터치 조작감과 글자 크기
- 1장을 끝낸 뒤 "이어하기"를 누르면 마지막 전투(장각)를 다시 하게 된다. 2장을 만들 때 정리할 것.
- 스킬 강화, 장비, 병종 승급, 운명 전투는 아직 구현하지 않았다(설계 문서에만 있음).
- 그래픽은 여전히 원형 말에 한글 한 글자다.
